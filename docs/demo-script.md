# 데모 흐름 — 분석 보고서가 아닌 배포 실행

1. API 키·모델과 Docker 실행 환경을 준비하고 서버를 시작한다.
2. examples/unready-node를 ZIP으로 만든다. 시작 스크립트와 Dockerfile이 없고 localhost에 묶여 있음을 보여준다.
3. 앱을 선택하고 Local Docker 대상에 배포하기를 한 번 누른다.
4. 파일 읽기·코드 수정·빌드·실행이 실제로 진행되는 로그를 보여준다.
5. 실패했다면 AI가 결과를 확인하고 수정·재시도하는 과정을 보여준다. 실패를 억지로 만들 필요는 없다.
6. 접속 URL에서 원래 앱 응답을 확인한다. 작업 내역에서 변경 diff와 원본 보존을 확인한다.

필수 환경변수가 있는 앱은 입력 대기 후 값을 넣어 배포를 이어가는 과정을 추가로 보여줄 수 있다.
데모 시간은 실제 API 응답·이미지 빌드 시간을 측정한 뒤 조정한다.

## 검증과 발표의 구분

`tests/smoke_agent.py`는 기본적으로 AI의 선택만 고정 테스트 응답을 사용한다.
이는 앱 업로드부터 실제 Docker 배포 및 실패 후 복구까지 검증하는 개발용 테스트다.
발표에서 이를 실제 AI 판단으로 소개하면 안 된다. 실제 AI 데모는 API 키를 설정하고 `--live` 검증 후 진행한다.
Cloud Run 경로는 CLI·프로젝트가 설정된 뒤 실제 앱 URL 검증에 성공한 경우에만 시연한다.
AWS ECS Express 경로는 실제 서울 리전 계정에서 샘플 앱의 공개 HTTPS 200 응답을 확인했다.
업로드 API부터 테스트용 고정 도구 호출, 소스 수정, AWS 배포, 상태 재검사까지의 통합 smoke도 통과했다.
같은 앱 ID로 AWS 서비스를 v1→v2 업데이트해 URL이 유지되고 응답이 바뀌는 smoke도 통과했다.
실제 AI API 판단을 사용한 데모와는 구분한다.
실패한 AWS 업데이트가 아직 진행 중일 때의 롤백 요청은 단위 테스트로만 확인했다.
완료된 AWS 릴리스는 같은 서비스의 성공 이력을 선택해 태스크 정의로 재배포하는 버튼을 제공한다.
시연할 때는 동일 URL의 v2 응답을 먼저 확인하고, 롤백 완료 후 v1 응답과 활성 릴리스 표시를 확인한다.
