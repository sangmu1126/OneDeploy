# AWS 일시 중지 기록 — 2026-10-03

대상은 계정 `265233844540`, 서울 리전 `ap-northeast-2`의 OneDeploy 데모 자원이다. 현재 형태를 [Terraform 구성](../terraform/aws-live/README.md)에 적고, 공유 CloudFormation 스택·`demo-app` DB 스택·별도 앱 서비스 보안 그룹·ECS Express 데모 서비스를 로컬 Terraform 상태에 import했다. provider 잠금 파일과 구성은 Git으로 관리하고, 자원 메타데이터가 담긴 상태 파일은 Git에서 제외한다. 이 작업에서 Terraform `apply`는 실행하지 않았다.

중지 전에 `onedeploy-demo-app-backup-20261002` 수동 스냅샷이 앱 소유·암호화·`available`이고 데모 ECR 이미지 태그 `8265dc56c6d74adf-a1`이 존재함을 확인했다. 임시 `dbdrill-*` 자원은 없었다. ECS Express의 최소 태스크를 0으로 바꾸고, 기본 ECS 서비스 목표 태스크를 0으로 설정했다. RDS `onedeploy-demo-app`에는 데이터 삭제 없이 일시 중지를 요청했다. 마지막 실제 상태 확인을 아래에 기록한다.

마지막 AWS 재조회에서 RDS는 `stopped`·삭제 보호 켜짐, ECS Express 서비스는 `ACTIVE`이나 최소 태스크 0개, 기본 ECS 서비스는 목표·실행 태스크 모두 0개이고 실행 태스크 목록은 비었다. `onedeploy-core`와 `onedeploy-db-demo-app` 스택은 `CREATE_COMPLETE`로 보존됐다. 수동 스냅샷은 `available`·암호화 상태이고 데모 ECR 이미지 태그도 남아 있다. 임시 `dbdrill-*` 자원은 이번 중지 작업에서 생성하지 않았다.

서비스와 로드 밸런서, ECR 저장소, 두 CloudFormation 스택, 보안 그룹, DB 저장소와 백업은 남는다. 태스크가 0개여도 로드 밸런서 및 저장소 비용은 계속 발생할 수 있다. RDS는 중지 후 7일이 지나면 AWS가 자동으로 다시 시작할 수 있다. [RDS 중지 동작](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_StopInstance.html), [ECS Express가 만드는 자원](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/express-service-work.html).

내일 재개할 때는 [Terraform 디렉터리의 실행 순서](../terraform/aws-live/README.md)를 사용한다. DB를 먼저 `available`로 만든 뒤 ECS 최소·목표 태스크를 1로 복원하고 공개 HTTP 응답과 DB 연결을 검증한다. Terraform plan의 ECS provider 제안 1건을 검토하기 전에는 apply하지 않는다.
