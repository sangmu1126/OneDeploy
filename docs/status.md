# OneDeploy 현재 상태와 남은 작업

기준: 2026-10-01. 이 문서는 현재 상태를 요약한다. 행사 원문과의 대조는
[요구사항](requirements.md), 구현 구조는 [설계](design.md), AWS 데이터 경로의
구체적인 경계와 명령은 [AWS 데이터 경로](aws-database-path.md), 결정 이유와 과거
검증 기록은 [의사결정 기록](decision-log.md)을 따른다.

## 확인된 경로

- Local Docker와 AWS ECS Express의 무상태 HTTP 앱은 실제 빌드·배포·HTTP 응답을 확인했다.
  AWS에서는 같은 앱 ID의 업데이트와 URL 유지도 확인했다. 이 실계정 경로의 AI 판단은
  테스트용 고정 응답이었다.
- 앱 업로드, 작업용 소스 변경, 자동 대상 선택, 배포 실패 재시도, 상태 확인,
  AWS 릴리스 복구 및 리소스 종료 코드가 있다. 실제 OpenAI API를 사용하는 끝단 검증은
  현재 개발 환경에 키가 없어 수행하지 못했다.
- PostgreSQL 경로에는 RDS 스택 템플릿·읽기 전용 사전 점검·가격 조회·기존 DB
  바인딩·비밀 주입·SQL 마이그레이션·데이터 읽기/쓰기 smoke가 구현돼 있다.
  2026-10-01 서울 리전에서 대상 계정, 기본 VPC, 두 가용 영역, 서비스 보안 그룹,
  PostgreSQL 18.3의 `db.t4g.micro`/암호화된 `gp3` 20 GiB 주문 가능 구성과
  기본 용량의 730시간 기준 공개 가격 20.87 USD를 읽기 전용으로 확인했다.
  이는 총비용이 아니며 RDS 스택이나 인스턴스를 생성한 검증도 아니다.
  해당 계정에는 확인 시점에 OneDeploy DB 스택·인스턴스가 없었다.
  기존 OneDeploy 보안 그룹은 다른 실행 중 ECS 서비스에 연결돼 있어 DB 앱에
  재사용하지 않는다. 앱 전용 그룹을 별도로 준비해야 한다.
- Cloud Run은 어댑터와 테스트가 있지만 실제 GCP 배포는 검증하지 않았다.

## 우선순위별 남은 작업

1. **AWS PostgreSQL 실계정 데이터 경로 검증.** 앱 ID와 비용 부담 범위를 정한 뒤
   RDS 스택을 명시적으로 생성한다. 생성 결과·소유권·비공개 연결을 확인하고
   `tests/smoke_aws_postgres.py`로 마이그레이션, 쓰기/읽기, 같은 서비스의 업데이트,
   데이터 보존과 임시 ECS 리소스 정리를 확인한다. RDS·비밀은 자동 폐기하지 않는다.
   생성·검증 순서는 [실계정 검증 절차](aws-postgres-live-runbook.md)에 정리했다.
2. **DB 앱의 단일 사용자 흐름 완성.** 현재 업로드 API는 기존 OneDeploy RDS를
   헤더로 명시해야 하고 UI는 DB 앱을 차단한다. 실제 데이터 경로가 통과한 뒤
   앱 요구 탐지 → DB 생성/기존 DB 선택 → 계정·비용·비밀·네트워크 확인 → 배포까지
   연결하고, 실패·재시작 시 불확실한 생성 결과를 재확인하는 절차를 완성한다.
3. **데이터 수명주기와 복구 검증.** 앱 배포 실패·업데이트·서비스 종료가 DB를
   삭제하지 않는지 실계정에서 확인한다. 스냅샷과 명시적 DB 폐기 절차, 백업·복구
   검증은 아직 없다. SQLite의 기존 데이터 이전도 지원하지 않는다.
4. **실제 AI 끝단 검증.** 사용 가능한 키·모델로 코드 변경 판단과 자동 대상 선택을
   실제 호출하고, 업로드부터 AWS HTTP 응답까지 실행한다. 고정 응답 smoke의 결과를
   실제 모델 정확도 증거로 사용하지 않는다.
5. **운영 범위 확장.** Cloud Run 실계정 검증, 다중 사용자 격리, 실행 중 취소,
   비용 상한/예산 통제, CI/CD 연동, 비 AWS 대상의 URL 고정·릴리스 복구는 남아 있다.
   이들은 AWS PostgreSQL 단일 경로를 완성하는 작업보다 후순위다.

현재 일반 UI에서는 영속 DB·파일 저장·별도 워커가 필요한 앱을 차단한다.
PostgreSQL 내부/API 경로가 있다는 것과 제품에서 원클릭으로 지원한다는 것은 다르다.
