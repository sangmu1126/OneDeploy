앱을 올리세요. AI가 배포에 필요한 설정과 코드를 준비하고, 실제 실행까지 진행합니다.

앱 배포

폴더를 바로 선택하거나 아래에서 ZIP을 선택하세요. Node.js 앱에는 package.json, 다른 런타임 앱에는 Dockerfile이 필요합니다. .env, .git, node_modules 등은 업로드하지 않습니다.

같은 앱 ID의 배포 이력을 묶습니다. AWS 배포는 기존 서비스를 업데이트해 URL을 유지합니다. Local Docker와 Cloud Run은 릴리스마다 별도 URL을 만듭니다.

이 앱 ID로 이미 만든 RDS만 연결합니다. 새 DB는 생성하지 않으며, 앱에는 migrations/ SQL 파일과 PGHOST·PGUSER·PGPASSWORD·PGDATABASE 방식의 연결이 필요합니다. ECS 서비스·로드 밸런서 비용과 기존 RDS 비용이 발생합니다. 앱 종료 후에도 RDS와 데이터는 남습니다.

서버에는 AWS 계정 ID와 이 앱 전용 서비스 보안 그룹 설정 또는 검증된 앱 네트워크 스택이 필요합니다. 배포 요청 전에 서버가 기존 DB 소유권과 네트워크를 확인합니다.

새 PostgreSQL RDS 생성 계획 미리보기

계획 조회는 DB를 생성하지 않습니다. 생성 버튼은 계획 확인 후에만 활성화됩니다. 같은 앱 ID의 스택 기록이 있으면 새 DB 계획을 거부하므로 기존 RDS 조회를 사용하세요. 먼저 앱 전용 서비스 보안 그룹을 서버에 지정하거나 앱 네트워크 스택을 준비하세요. 생성된 RDS는 앱 배포 실패·종료 후에도 보존되고 비용이 계속 발생합니다. 예상 금액은 RDS 인스턴스 730시간과 20 GiB 저장소 용량만 포함합니다.

앱 전용 AWS 네트워크 준비

서버에 고정 서비스 보안 그룹이 없을 때 이 앱 ID의 ECS 서비스 보안 그룹을 만듭니다. 계획 확인은 읽기 전용이며 생성 버튼을 누를 때만 CloudFormation 스택을 생성합니다. 그룹은 앱 종료 후에도 남습니다.

작업용 복사본을 수정하므로 원본 앱은 유지됩니다. 배포 중 코드 일부와 실행 로그를 AI에 전송합니다. 직접 만든 신뢰할 수 있는 앱을 사용하세요.
